# ЛР №3, вариант 5 — SHA-256 mixer

Состав: `rngdriver.c`, `rngdriver.h`, `user.c`, `Makefile`.

## Что реализовано
- Клавиатура: Linux Input Subsystem (`input_handler`), событие нажатия клавиши.
- Сеть: Netfilter IPv4 `NF_INET_LOCAL_IN`, входящие пакеты локальному хосту.
- Оба обработчика помещают timestamp/source/sequence в общую ограниченную очередь.
- `workqueue` обновляет единое 32-байтовое состояние:
  `pool = SHA256(pool || event)`.
- `/dev/rngdriver`: блокирующее чтение до поступления нового события; до 32 байт на один успешный `read`.
- `ioctl`: статистика и сброс.
- Пользовательская программа выполняет частотный тест, тест серий, среднее и дисперсию байтов.

## Сборка
Нужны заголовки именно запущенного ядра:
```bash
make
```
Если `KDIR` не подходит:
```bash
make KDIR=/путь/к/headers
```

## Запуск
```bash
sudo insmod rngdriver.ko
dmesg | tail
```
Сгенерировать события: нажимать клавиши в гостевой системе и отправлять IPv4-трафик на IP гостевой VM (например, `ping IP_VM` с хоста).

Во втором терминале:
```bash
sudo ./rng_user 4096
```
Выгрузка:
```bash
sudo rmmod rngdriver
```

## Важные ограничения
1. Это учебный миксер, не криптографически сертифицированный ГСЧ.
2. Количество событий и смешанных байт не равно числу бит энтропии. SHA-256 перемешивает вход, но не создаёт непредсказуемость.
3. Для ARM64 используется Input Subsystem, а не жёстко заданный PC IRQ 1. Timestamp снимается при доставке события в input handler.
4. `LOCAL_IN` видит IPv4-пакеты, адресованные локальному хосту, а не весь транзитный трафик.
5. Простые статистические тесты не доказывают криптографическую случайность.
